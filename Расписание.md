План до 14 июня**

**3-4 июня:** запуск и стабилизация основы  
Починить `Dockerfile`, `docker-compose.yaml`, `.env`, порт backend/frontend, CORS, Vite proxy. Backend должен стабильно запускаться на FastAPI, frontend должен ходить в `/api`.

**5-7 июня:** перенос API на FastAPI  
В первую очередь переносить:
- `auth`
- `users`
- `tournaments`
- `athletes`
- `clubs`
- `categories`
- `dans`
- `weighing`

После этого уже:
- `brackets`
- `fights`
- `scores`
- `results`
- `statistics`
- `pdf`

Главная цель: чтобы все frontend-запросы получали ответ, даже если часть логики пока простая.

**8-9 июня:** новый функционал  
Добавлять только то, что реально нужно для диплома/демо. Все “приятные улучшения” отложить. Сначала список must-have, потом остальное.

**10-11 июня:** ошибки и интеграция  
Пройти весь пользовательский путь:
- регистрация/логин
- создание турнира
- категории
- спортсмены
- клубы
- регистрация на турнир
- взвешивание
- генерация сетки
- проведение боя
- результаты/PDF

**12-13 июня:** интерфейс под экран  
Подгонка frontend под ноутбук/проектор/экран защиты:
- адаптивность таблиц
- чтобы кнопки не вылезали
- scoreboard/fight screen под нужное разрешение
- нормальные отступы
- читаемые шрифты
- убрать визуальные баги

**14 июня:** только финальная проверка  
В этот день лучше ничего крупного не переписывать. Только запуск, демо-сценарий, резервный план.

**Как работать со мной эффективно**

Каждый день лучше давать мне конкретную задачу:

1. “Перенеси `weighing.py` с Flask на FastAPI.”
2. “Почини proxy frontend к backend.”
3. “Сравни frontend fetch-запросы с backend routes.”
4. “Сделай экран боев адаптивным под 1920x1080.”
5. “Проверь ошибки запуска backend.”

Самый разумный режим: **каждый день 2 блока по 3-4 часа**. Один блок backend/API, второй блок frontend/ошибки. И обязательно в конце дня 30 минут на проверку всего сценария.
